# Schema + migrations

- Alembic only. Use the `new-migration` skill. Review every autogenerated diff by hand, since autogenerate misses RLS policies, materialized views, trigram indexes and enum changes.
- Every household-data table has `household_id NOT NULL` + an RLS policy (`USING (household_id = current_setting('app.household_id')::uuid)`) + an index. The app connects as a non-superuser role so RLS actually applies.
- Money columns follow the money rule (`NUMERIC(14,2)`). Timestamps are `timestamptz`, and dates that are calendar dates are `date`.
- Reporting views the agent may read are named `v_*` and documented in `backend/app/agent/tools.py`'s whitelist.
- Every migration has a working `downgrade()` and is tested up→down→up in CI.
- No destructive migration (drop/rename of a column with data) without a backfill step and a note in the phase report.
